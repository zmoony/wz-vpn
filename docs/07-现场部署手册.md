# Pi-Gateway 现场部署手册

> 适用对象：首次把 Pi-Gateway 部署到现场 Linux 服务器的实施人员。  
> 适用版本：当前仓库主干代码。  
> 推荐目标环境：Raspberry Pi OS Bookworm 64-bit / Debian 12 ARM64。

## 1. 部署目标

本项目当前的部署形态是：

- `pi-gateway` 后端单二进制
- Vue 前端静态文件由后端托管
- SQLite 本地存储
- `systemd` 管理主进程
- 宿主机原生依赖：`nginx`、`wireguard`、`nftables`、`ddns-go`、`acme.sh`

安装脚本会完成：

- 创建 `/opt/pi-gateway` 目录结构
- 安装 `pi-gateway` 二进制
- 复制 `web/dist` 静态资源
- 安装环境变量文件
- 安装并启用 `pi-gateway.service`

安装脚本不会自动完成：

- `apt` 安装系统依赖
- 下载 `ddns-go`
- 安装 `acme.sh`
- 创建 `ddns-go.service`
- 初始化 `WireGuard` 服务端配置
- 调整 `nftables` 开机加载规则

所以现场部署建议按“系统准备 -> 构建产物 -> 安装 Pi-Gateway -> 安装外围依赖 -> 首次配置 -> 验证”的顺序执行。

## 2. 当前版本的已知限制

在正式部署前，请先知晓这几个限制：

1. 反向代理、防火墙、WireGuard、DDNS、证书都依赖宿主机已有可执行命令和正确权限。
   说明：如果 `nginx`、`nft`、`wg`、`conntrack`、`ddns-go` 不存在，页面可以打开，但相关真实操作会失败。

2. 当前安装脚本默认以 `root` 运行 `pi-gateway.service`。
   说明：这是为了先跑通 `wg`、`nft`、`nginx reload` 等系统能力，后续再考虑最小权限收敛。

## 3. 部署前准备

至少准备以下信息：

- 管理面板管理员账号和密码
- 根域名，例如 `example.com`
- WireGuard Endpoint，例如 `vpn.example.com:51820`
- WireGuard 服务端公钥
- 家庭内网 DNS，例如 `192.168.1.1`
- 阿里云 DNS 子账号 `AccessKey ID / Secret`
- 目标服务器 SSH 访问权限

建议提前确认：

- 服务器已启用 IPv6 公网
- 域名解析托管在阿里云 DNS
- 计划暴露的 80/443/51820 端口已允许入站
- 8443 管理面板端口默认不要直接暴露公网

## 4. 目标机系统准备

以下命令在目标 Linux 服务器执行。

### 4.1 更新系统

```bash
sudo apt update
sudo apt upgrade -y
```

### 4.2 安装基础依赖

```bash
sudo apt install -y nginx wireguard nftables curl socat unzip conntrack
```

说明：

- `nginx`：反向代理
- `wireguard`：VPN 管理
- `nftables`：防火墙
- `conntrack`：防火墙页面的当前连接查看
- `curl` / `socat`：`acme.sh` 常用依赖

### 4.3 启用基础 systemd 服务

```bash
sudo systemctl enable nginx
sudo systemctl enable nftables
```

如果还没有启用 WireGuard 接口，可以后面在生成 `/etc/wireguard/wg0.conf` 后再启。

## 5. 构建部署产物

建议在有完整 Go / Node 环境的构建机执行，而不是直接在现场服务器编译。

### 5.1 构建前端

```bash
cd web
npm install
npm run build
cd ..
```

### 5.2 构建 Linux ARM64 二进制

树莓派 4/5 通常使用 ARM64：

```bash
set GOOS=linux
set GOARCH=arm64
go build -o pi-gateway ./cmd/pi-gateway
```

如果你的构建机本身就是 Linux shell，也可以使用：

```bash
GOOS=linux GOARCH=arm64 go build -o pi-gateway ./cmd/pi-gateway
```

如果目标机是 x86_64 Debian，请把 `GOARCH` 改成 `amd64`。

### 5.3 准备需要上传的文件

至少上传这些内容到现场服务器：

- `pi-gateway`
- `web/dist/`
- `.env.example`
- `scripts/install.sh`
- `deploy/pi-gateway.service`

如果你直接上传整个仓库，也可以，但现场执行安装脚本前请确认根目录里已经有编译好的 `pi-gateway`。

## 6. 上传到现场服务器

示例：

```bash
scp -r ./pi-gateway ./web/dist ./.env.example ./scripts ./deploy user@server:/tmp/pi-gateway-release/
```

上传后在服务器上确认：

```bash
ls -la /tmp/pi-gateway-release
```

应至少看到：

- `pi-gateway`
- `web/dist`
- `.env.example`
- `scripts/install.sh`
- `deploy/pi-gateway.service`

## 7. 安装 Pi-Gateway

在目标机执行：

```bash
cd /tmp/pi-gateway-release
chmod +x scripts/install.sh
sudo ./scripts/install.sh
```

脚本默认会安装到：

- 二进制：`/opt/pi-gateway/bin/pi-gateway`
- 环境文件：`/opt/pi-gateway/etc/pi-gateway.env`
- 数据目录：`/opt/pi-gateway/data`
- 前端静态资源：`/opt/pi-gateway/web/dist`
- systemd unit：`/etc/systemd/system/pi-gateway.service`

安装后可检查：

```bash
sudo systemctl status pi-gateway --no-pager
```

## 8. 修改环境变量

编辑：

```bash
sudo nano /opt/pi-gateway/etc/pi-gateway.env
```

至少应修改以下项：

```env
PI_GATEWAY_ENV=production
PI_GATEWAY_LISTEN_ADDR=:8443

PI_GATEWAY_JWT_SECRET=换成随机长字符串
PI_GATEWAY_ADMIN_USER=admin
PI_GATEWAY_ADMIN_PASS=换成强密码

PI_GATEWAY_WG_IFACE=wg0
PI_GATEWAY_WG_SUBNET_V4=10.66.66.0/24
PI_GATEWAY_WG_SERVER_V4=10.66.66.1/24
PI_GATEWAY_WG_DNS=192.168.1.1
PI_GATEWAY_WG_ENDPOINT=vpn.example.com:51820
PI_GATEWAY_WG_PUBLIC_KEY=填入服务端公钥

PI_GATEWAY_NGINX_SITES_DIR=/opt/pi-gateway/data/nginx/sites-enabled
PI_GATEWAY_DDNSGO_CONFIG_PATH=/opt/pi-gateway/data/ddns-go/config.json
PI_GATEWAY_DDNSGO_STATUS_PATH=/opt/pi-gateway/data/ddns-go/status.json
PI_GATEWAY_CERTS_INSTALL_ROOT=/opt/pi-gateway/data/certs
PI_GATEWAY_NFTABLES_RULES_PATH=/opt/pi-gateway/data/nftables/pi-gateway.nft
PI_GATEWAY_FIREWALL_STATE_PATH=/opt/pi-gateway/data/nftables/pending-apply.json
PI_GATEWAY_FIREWALL_BACKUPS_DIR=/opt/pi-gateway/data/nftables/backups
```

建议暂时不要把管理面板监听到 `0.0.0.0:8443`。  
更安全的做法是：

- 先只在内网访问
- 或配合 SSH 隧道访问
- 或后续通过反向代理和额外鉴权再暴露

## 9. 安装外围依赖

### 9.1 安装 ddns-go

当前项目只负责读写受管配置和状态文件，不负责自动下载 `ddns-go`。

可按你的目标版本自行下载，例如：

```bash
sudo mkdir -p /opt/ddns-go
cd /opt/ddns-go
sudo curl -L -o ddns-go.tar.gz <请替换为 ddns-go Linux ARM64 发布包地址>
sudo tar -xzf ddns-go.tar.gz
sudo chmod +x ddns-go
```

然后自建 `ddns-go.service`，并确保它读取或兼容：

- `/opt/pi-gateway/data/ddns-go/config.json`
- `/opt/pi-gateway/data/ddns-go/status.json`

如果你已经有自己的 `ddns-go` 部署方式，也可以只把：

- `PI_GATEWAY_DDNSGO_CONFIG_PATH`
- `PI_GATEWAY_DDNSGO_STATUS_PATH`
- `PI_GATEWAY_DDNSGO_RELOAD_COMMAND`

改成与你现场一致的路径和 reload 命令。

### 9.2 安装 acme.sh

```bash
curl https://get.acme.sh | sh
```

安装完成后确认：

```bash
~/.acme.sh/acme.sh --version
```

并在 env 中保留：

```env
PI_GATEWAY_ACME_SH_PATH=/root/.acme.sh/acme.sh
```

说明：当前证书模块已经改成 Linux 原生命令调用模式，现场仍需确认：

- `PI_GATEWAY_ACME_SH_PATH` 指向真实可执行的 `acme.sh`
- 进程用户对证书安装目录有写权限
- `Ali_Key` / `Ali_Secret` 对应的阿里云子账号具备 DNS 修改权限

### 9.3 准备 nginx

确认 nginx 可正常执行：

```bash
sudo nginx -t
```

如果你希望由面板管理的站点目录被 nginx 加载，需要确认主配置已经包含相应目录。  
当前默认 env 指向：

```text
/opt/pi-gateway/data/nginx/sites-enabled
```

因此建议在 nginx 主配置中增加一段 include，例如：

```nginx
include /opt/pi-gateway/data/nginx/sites-enabled/*.conf;
```

加完后执行：

```bash
sudo nginx -t
sudo systemctl reload nginx
```

### 9.4 准备 nftables

面板会把规则写到：

```text
/opt/pi-gateway/data/nftables/pi-gateway.nft
```

并在应用时执行：

```bash
nft -f /opt/pi-gateway/data/nftables/pi-gateway.nft
```

如果你希望重启后自动恢复这份规则，建议在 `/etc/nftables.conf` 中显式 include：

```nft
include "/opt/pi-gateway/data/nftables/pi-gateway.nft"
```

但首次上线时请谨慎操作，建议先在面板里预览并应用，再决定是否加入系统开机加载。

### 9.5 准备 WireGuard

当前面板会调用 `wg` 命令，并读写 `/etc/wireguard/wg0.conf`。  
建议先手工准备服务端基础配置和密钥，再交给面板继续管理 peer。

至少确认：

```bash
sudo test -f /etc/wireguard/wg0.conf
sudo wg show
```

如果还没有服务端密钥，可参考：

```bash
umask 077
wg genkey | tee server_private.key | wg pubkey > server_public.key
```

然后把公钥填回：

```env
PI_GATEWAY_WG_PUBLIC_KEY=这里填 server_public.key 的内容
```

## 10. 重启主服务

环境变量修改后执行：

```bash
sudo systemctl restart pi-gateway
sudo systemctl status pi-gateway --no-pager
```

查看日志：

```bash
sudo journalctl -u pi-gateway -n 100 --no-pager
```

## 11. 首次访问

在内网浏览器打开：

```text
http://服务器IP:8443/login
```

使用 env 中配置的账号密码登录。

建议的首次操作顺序：

1. 打开“设置”页，确认 WireGuard 基础参数
2. 打开“防火墙”页，先预览默认规则，不要急着 apply
3. 打开“DDNS”页，填阿里云 DNS 配置
4. 打开“证书”页，只先确认配置结构，不要在当前版本直接执行签发
5. 打开“反向代理”页，先完成证书关联和上游地址配置
6. 打开“WireGuard”页，再开始创建 peer

## 12. 现场验收清单

### 12.1 主服务

```bash
curl http://127.0.0.1:8443/api/healthz
```

期望返回：

```json
{"status":"ok"}
```

### 12.2 nginx

```bash
sudo nginx -t
```

### 12.3 nftables

```bash
sudo nft list ruleset
```

### 12.4 WireGuard

```bash
sudo wg show
```

### 12.5 ddns-go

```bash
sudo systemctl status ddns-go --no-pager
```

### 12.6 conntrack

```bash
conntrack -L | head
```

如果这一步失败，防火墙页的“当前连接”区块会不可用，但不影响其它防火墙功能。

## 13. 常见问题排查

### 13.1 页面能打开，但很多功能操作失败

通常是宿主机缺命令或权限不足。重点检查：

- `nginx -t`
- `nft -f`
- `wg show`
- `conntrack -L`
- `ddns-go`

### 13.2 页面空白或模块空白

先看浏览器控制台，再看后端日志：

```bash
sudo journalctl -u pi-gateway -n 100 --no-pager
```

### 13.3 防火墙 apply 风险

当前面板支持 30 秒确认和自动回滚，但现场仍建议：

- SSH 保持不断开
- 第一次只放最小规则
- 确认可访问后再继续细化

### 13.4 证书申请失败

优先检查：

- `PI_GATEWAY_ACME_SH_PATH` 是否正确
- `acme.sh --version` 是否能正常执行
- 阿里云 `AccessKey ID / Secret` 是否正确
- 域名是否确实托管在阿里云 DNS
- 证书安装目录是否可写

## 14. 推荐的上线策略

如果现场时间紧，我建议按下面节奏上线：

1. 先部署主面板、SQLite、前端静态资源
2. 先验证“登录 / 设置 / 系统状态 / WireGuard 列表 / 防火墙预览”
3. 再接入 `nginx`
4. 再接入 `ddns-go`
5. 证书模块在确认 `acme.sh` 和阿里云凭据可用后再开
6. 防火墙 apply 放在有人值守时执行

这样比“一次把所有功能全打开”更稳。
