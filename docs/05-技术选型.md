## 2. 关键组件详细选型理由

### 2.1 反向代理：裸 nginx

| 维度 | 裸 nginx | NPM | Caddy | Traefik |
|---|---|---|---|---|
| 依赖 Docker | 不需要 | 强依赖 | 不需要 | 不需要 |
| 管控灵活度 | 完全控制 vhost 文件 | 通过 API | 通过 Caddyfile | 通过 YAML/API |
| 面板集成难度 | 模板渲染即可 | 调 API | 中 | 中 |
| 树莓派资源 | apt 装好 ~20 MB | 容器 ~200 MB | ~40 MB | ~80 MB |
| 证书集成 | 需搭配 acme.sh | 内置 | 内置 | 内置 |
| 社区/文档 | 最丰富 | 中 | 较好 | 中 |

**结论**：去容器化后，NPM 不再适用（NPM 强依赖 Docker）。裸 nginx 是 Debian 标配，`apt install` 即可，面板通过模板渲染 vhost 文件控制反代，灵活度最高。证书由 acme.sh 独立管理，不让 nginx 操心。

### 2.2 证书工具：acme.sh

| 维度 | acme.sh | certbot | lego |
|---|---|---|---|
| 实现语言 | shell | python | go |
| 阿里云 DNS-01 | 官方 dns_ali | 需第三方插件 | 支持 |
| 安装方式 | curl 一键安装 | apt install | 下载二进制 |
| 续期机制 | cron / systemd timer | systemd timer | 需自定义 |
| 体积 | < 5 MB | ~50 MB (含 venv) | ~20 MB |

**结论**：acme.sh 宿主机安装最轻量，阿里云插件成熟，systemd timer 做续期。

### 2.3 DDNS：ddns-go

- 单一职责：只管 DDNS
- 支持阿里云 / 腾讯云 / Cloudflare / 华为云等主流
- 支持 IPv6
- 单二进制 Go 实现，ARM64 二进制 < 15 MB
- 开源社区活跃（GitHub > 10k stars）
- 作为 systemd 服务运行，无需 Docker

**为什么不让面板自己实现 DDNS**：
- 重复造轮子无收益
- ddns-go 已经处理了运营商各种 IPv6 边缘情况（多前缀、临时地址、隐私扩展）
- 出问题方便单独定位

### 2.4 VPN：WireGuard

- 树莓派内核态支持，性能比 OpenVPN 高一个数量级
- `apt install wireguard` 一行搞定
- 配置极简（一个 ini 文件）
- 客户端生态全平台
- IPv6 原生
- 完全自主可控

### 2.5 防火墙：nftables

| 维度 | nftables | iptables | ufw | firewalld |
|---|---|---|---|---|
| Debian 12 默认 | 是 | 兼容层 | 前端 | 前端 |
| IPv4 + IPv6 统一 | 一套规则 | 分 iptables/ip6tables | 统一 | 统一 |
| 编程友好度 | nft 命令 + 规则文件 | 长链条命令 | 简单但不灵活 | 区域概念好但重 |
| 原子加载 | `nft -f` 原子替换 | 无 | 无 | 有 |
| 可读性 | 好 | 差 | 好 | 中 |
| 适合面板管理 | 生成规则文件 + 原子加载 | 逐条执行命令 | 太简单 | XML 配置重 |

**结论**：nftables 是 Linux 防火墙的未来方向，Debian 12 默认内核支持。面板生成 `.nft` 规则文件然后 `nft -f` 原子加载，天然适合"预览 → 应用 → 回滚"的安全模式。IPv4/IPv6 用一套 `inet` 族规则统一管理，比 iptables 干净得多。

### 2.6 后端语言：Go

| 维度 | Go | Python (FastAPI) | Node (NestJS) | Rust (axum) |
|---|---|---|---|---|
| 部署体积 | 单二进制 < 30 MB | venv 一坨 + 解释器 | node_modules 巨大 | 单二进制 < 10 MB |
| 内存占用（idle） | ~30 MB | ~80 MB | ~120 MB | ~10 MB |
| ARM64 交叉编译 | `GOOS=linux GOARCH=arm64` 一行 | 麻烦 | 麻烦 | 一行 |
| 调系统命令 | `exec.Command` 简洁 | subprocess | child_process | std::process |
| 学习曲线 | 平 | 平 | 中 | 陡 |

**结论**：Go 是树莓派单二进制场景下的最佳选择。

### 2.7 前端：Vue 3 + Element-Plus

- Vue 3 + Composition API 是后端工程师最容易上手的前端框架
- Element-Plus 组件齐全（表格、表单、抽屉、消息），文档中文
- 拖拽排序库（vuedraggable-plus）用于防火墙规则排序
- 体积可接受（Vite 构建 gzip ~ 150 KB）

### 2.8 持久化：SQLite

- 数据量极小（用户表、服务导航、防火墙规则、审计日志，永远 < 100 MB）
- 单文件，备份就是 `cp app.db backup.db`
- 零运维（不需要起数据库服务）
- Go 端用 `modernc.org/sqlite`（纯 Go 实现，无 CGO，方便交叉编译）

### 2.9 IPv4 兜底：Cloudflare Tunnel

**优点**：
- 免费
- 零端口（不需要打开任何入站端口）
- 自带 anti-DDoS
- cloudflared 单二进制，作为 systemd 服务运行

**缺点**：
- 仅支持 HTTP/HTTPS（不支持 UDP，不能代替 WireGuard 入口）
- 国内访问 Cloudflare 边缘节点延迟波动较大

**与"域名在阿里云"的并存方案**：
- 主域 `example.com` 仍在阿里云
- 需要走 Tunnel 的子域在阿里云加 CNAME 指向 Cloudflare Tunnel 的 `<uuid>.cfargotunnel.com`

## 3. 版本兼容性约束

| 组件 | 最低版本 | 原因 |
|---|---|---|
| Linux Kernel | 5.6 | WireGuard 内核态 + nftables 完整支持 |
| Debian / Pi OS | 12 (Bookworm) | nftables 默认、nginx 1.22+、systemd 252+ |
| Go | 1.22 | 部分依赖要求 |
| Node.js（构建期） | 20 LTS | Vite 5 / Vue 3.4 |
| SQLite | 3.35 | UPSERT 语法 |
| nftables | 1.0.2 | inet 族完整支持 |
| nginx | 1.22 | HTTP/2 + proxy_pass 完善 |

## 4. 不选用的方案及原因

| 方案 | 不选原因 |
|---|---|
| Docker / Docker Compose | 用户明确要求不容器化；树莓派资源有限，减少一层抽象 |
| Nginx Proxy Manager (NPM) | 强依赖 Docker，去容器化后不可用 |
| Lucky（gdy666/lucky）现成 | 用户要求"自研、自主可控" |
| Tailscale | 依赖官方协调服务器，违反"自主可控"目标 |
| Headscale | 多一层抽象、多一个组件维护 |
| OpenVPN | 性能差、配置重 |
| Caddy 替代 nginx | nginx 社区文档更丰富、树莓派标配 |
| iptables | nftables 是继任者，iptables 规则可读性差 |
| ufw | 过于简单，不支持细粒度可视化管理 |
| firewalld | XML 配置过重，面板集成复杂 |
| Postgres / MySQL | 数据量根本撑不起，运维负担反而高 |
| Kubernetes / k3s | 单机家用场景过度设计 |
| React | 选型疲劳，不如 Vue 直接 |

## 5. 升级路径预留

- **数据库**：sqlite → postgres 通过 GORM 抽象层切换，仅改 DSN
- **VPN**：WireGuard → 加 Headscale 作为额外协议，并不替换 WG
- **反代**：当前已是裸 nginx，未来可考虑用 Go 模板引擎生成更复杂的 vhost
- **防火墙**：nftables 规则渲染引擎可扩展（GeoIP、rate-limit 等高级功能）
- **面板**：单实例 → 多实例（不在 v1.x 计划内，家用不需要）
