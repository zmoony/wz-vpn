# Pi-Gateway 架构设计

> 本文档描述系统的逻辑分层、网络拓扑、组件交互、数据流向。

---

## 1. 设计原则

1. **关注点分离**：公网入口（A）、远程接入（B）、防火墙（C）独立成层，互不依赖
2. **拥抱开源**：底层能力全部用成熟开源组件（nginx / WireGuard / acme.sh / ddns-go / nftables），管理面板只做"门面 + 编排"
3. **宿主机原生**：所有组件 apt 安装或单二进制部署，systemd 统一管理，不使用 Docker
4. **配置即数据**：所有可变配置落到 `/opt/pi-gateway/data/` 目录，便于备份和版本化
5. **面板可丢**：即使管理面板挂了，底层组件依然按已有配置工作

---

## 2. 系统分层

```text
L4  应用展示层  |  Vue3 + Element-Plus（浏览器中运行）
L3  管理面板层  |  Go + Gin，REST/WebSocket，sqlite 存元数据
L2  能力组件层  |  nginx / acme.sh / ddns-go / WireGuard / nftables
L1  基础设施层  |  systemd / 阿里云 DNS / Cloudflare
L0  硬件&网络   |  Raspberry Pi 4/5 + 家庭宽带（IPv6-only）
```

### L3 调用 L2 的方式

| L2 组件 | 管理面板调用方式 |
|---|---|
| nginx | 生成/修改 `/etc/nginx/sites-enabled/*.conf` vhost 文件 → `nginx -t && nginx -s reload` |
| WireGuard | 执行 `wg` / `wg-quick` 命令 + 读写 `/etc/wireguard/wg0.conf` |
| acme.sh | 执行 `~/.acme.sh/acme.sh` CLI；读 `data/acme/` 目录获取证书元数据 |
| ddns-go | 读 ddns-go 配置和日志（ddns-go 作为 systemd 服务独立运行） |
| nftables | 生成 `/etc/nftables.d/pi-gateway.nft` 规则文件 → `nft -f` 加载 |
| 系统状态 | 直接读 `/proc`、`/sys/class/thermal/`、`/sys/class/net/` |
| Cloudflare Tunnel | 通过 `cloudflared` CLI 或 Cloudflare API（可选） |

## 3. 网络拓扑

### 3.1 总览

```text
IPv6 客户端 (手机IPv6, 电脑IPv6)
        |
        | AAAA 解析
        v
   家庭光猫/路由 (IPv6 防火墙放行)
        |
        v
   树莓派 (Pi-Gateway)
        |
        +-- [nftables 防火墙] <-- 第一道关口，入站流量先过这里
        |       |
        |       +-- 放行 TCP 80/443      --> nginx
        |       +-- 放行 UDP 51820       --> WireGuard
        |       +-- 放行 TCP 22(可选)     --> SSH
        |       +-- 其他入站 DROP
        |
        +-- nginx 443/80            (公网入口，反代到内网各服务)
        +-- WireGuard UDP 51820     (VPN，10.66.66.0/24)
        +-- 管理面板 :8443          (仅内网/VPN 访问)
        +-- ddns-go                 (无端口对外)
        +-- acme.sh                 (无端口对外)
        |
        v
   家庭内网 (NAS / HA / Jellyfin / Git / SSH ...)


IPv4 客户端 (4G, 公司 WiFi 等 IPv4-only 网络)
        |
        v
   Cloudflare 边缘 (免费)
        |  Tunnel
        v
   树莓派 nginx (仅 HTTP/HTTPS 服务可走这条路)
```

### 3.2 端口规划

| 端口 | 协议 | 监听位置 | 是否公网 | 用途 |
|---|---|---|---|---|
| 80 | TCP | 0.0.0.0 | 是（IPv6） | nginx 重定向到 443 |
| 443 | TCP | 0.0.0.0 | 是（IPv6 + CF Tunnel） | nginx HTTPS 入口 |
| 51820 | UDP | 0.0.0.0 | 是（IPv6） | WireGuard |
| 8443 | TCP | 内网 + WG | 否 | 管理面板 HTTPS |
| 22 | TCP | 0.0.0.0 | 否（防火墙限制来源） | SSH（建议仅走 VPN） |

> **强制规则**：管理面板（8443）严禁暴露到公网，只允许：
> - 局域网 IP 直连
> - WireGuard 客户端通过 `10.66.66.1:8443` 访问

### 3.3 IP 网段规划

| 网段 | 用途 |
|---|---|
| `192.168.x.0/24` | 家庭原有内网（不动） |
| `10.66.66.0/24` | WireGuard v4 网段，树莓派端 `10.66.66.1` |
| `fd42:42:42::/64` | WireGuard v6 网段（可选） |

## 4. 数据流

### 4.1 DDNS 更新流

```text
ddns-go (systemd 服务)
  1. 定时检测当前公网 IPv6（通过网卡或外部接口查询）
  2. 与本地缓存对比，发现变化
  3. 调用阿里云 OpenAPI 更新 AAAA 记录
  4. 写日志到 journald
        |
        v
   阿里云 DNS

管理面板 -> 读 ddns-go 状态 -> 展示
```

### 4.2 证书签发流

```text
首次签发:
  管理面板 -> 调用宿主机 acme.sh
  -> acme.sh --issue --dns dns_ali -d "*.example.com" -d "example.com"
  -> 调用阿里云 OpenAPI 写 TXT 记录
  -> Let's Encrypt 验证 -> 颁发证书
  -> acme.sh --install-cert 写到 /opt/pi-gateway/data/certs/example.com/
  -> 面板触发 nginx -s reload

自动续期:
  acme.sh 通过 systemd timer，每天 0:00 检查到期；剩余 < 30 天则续期
  续期成功后执行 reloadcmd -> nginx -s reload
```

### 4.3 反向代理新增流

```text
浏览器 -> 面板填表（子域名/后端/证书）
       -> 面板后端:
            1. 根据模板生成 /etc/nginx/sites-enabled/<subdomain>.conf
            2. 执行 nginx -t（语法校验）
            3. 校验通过 -> nginx -s reload
            4. 校验失败 -> 删除文件、返回错误
       -> 公网请求 -> nginx -> 后端内网服务
```

### 4.4 WireGuard peer 新增流

```text
浏览器 -> 面板填表（名称）
       -> 面板后端:
            1. 从可用 IP 池分配 10.66.66.x
            2. 生成 keypair (wg genkey | wg pubkey)
            3. 追加 [Peer] 段到 wg0.conf
            4. 实时下发: wg set wg0 peer <pub> allowed-ips <ip>/32
            5. 生成客户端 conf 内容 + qrencode 出二维码 PNG
       -> 浏览器显示二维码 / 下载 conf 文件
```

### 4.5 防火墙规则变更流

```text
浏览器 -> 面板添加/修改/删除规则
       -> 面板后端:
            1. 在 sqlite 中更新规则集
            2. 根据规则集渲染 nftables 规则文件
            3. 用户点"预览" -> 返回最终 nft 规则文本
            4. 用户点"应用" ->
               a. 备份当前 /etc/nftables.d/pi-gateway.nft
               b. 写入新规则文件
               c. nft -f /etc/nftables.d/pi-gateway.nft
               d. 启动 30 秒回滚定时器
            5. 用户点"确认" -> 取消回滚定时器
            6. 30 秒无确认 -> 恢复备份文件 -> nft -f 回滚
```

## 6. 部署架构

### 6.1 安装方式

全部通过 `apt install` + 单二进制下载 + systemd：

```text
sudo apt install nginx wireguard nftables    # 系统包
# ddns-go: 从 GitHub releases 下载 ARM64 二进制
# acme.sh: curl 安装脚本
# pi-gateway: 下载预编译 ARM64 二进制
```

### 6.2 文件布局

```text
/opt/pi-gateway/                     安装根目录
  pi-gateway                         后端二进制 (ARM64)
  config.yaml                        主配置文件
  data/
    certs/                           acme.sh 签发的证书
    wireguard/                       wg 密钥备份（主配置在 /etc/wireguard/）
    app.db                           管理面板 sqlite
    logs/                            可选文件日志
  web/                               前端构建产物（内嵌到二进制或独立目录）
  scripts/
    install.sh                       一键安装
    update.sh                        一键升级

/etc/nginx/sites-enabled/            nginx vhost 配置（面板生成）
/etc/wireguard/wg0.conf              WireGuard 服务端配置
/etc/nftables.conf                   nftables 主配置（include pi-gateway 规则）
/etc/nftables.d/pi-gateway.nft       面板生成的防火墙规则
~/.acme.sh/                          acme.sh 安装目录和证书数据
```

### 6.3 systemd 服务清单

| 服务 | 单元名 | 说明 |
|---|---|---|
| nginx | `nginx.service` | 反向代理（apt 自带） |
| WireGuard | `wg-quick@wg0.service` | VPN（apt 自带） |
| nftables | `nftables.service` | 防火墙（apt 自带） |
| ddns-go | `ddns-go.service` | DDNS（自建 unit） |
| acme.sh 续期 | `acme-renew.timer` | 每日证书检查（自建 timer） |
| cloudflared | `cloudflared.service` | CF Tunnel（可选，自建 unit） |
| pi-gateway | `pi-gateway.service` | 管理面板（自建 unit） |

## 7. 关键技术决策记录（ADR 简版）

| ID | 决策 | 备选 | 选择理由 |
|---|---|---|---|
| ADR-01 | 反代用裸 nginx，不用 NPM/Caddy/Traefik | NPM, Caddy, Traefik | 不依赖 Docker；面板直接管 vhost 文件，灵活度最高；nginx 是树莓派标配 |
| ADR-02 | 证书用 acme.sh，不用 certbot | certbot, lego | acme.sh 阿里云插件成熟，shell 实现，无额外 runtime 依赖 |
| ADR-03 | DDNS 用 ddns-go，不用自己写 | 自己写 | ddns-go 开源、稳定、支持阿里云 IPv6 |
| ADR-04 | VPN 用 WireGuard，不用 OpenVPN | OpenVPN, Tailscale, ZeroTier | 性能 + 自主可控 + 树莓派友好 |
| ADR-05 | 防火墙用 nftables，不用 iptables/ufw | iptables, ufw, firewalld | Debian 12 默认；nftables 是 iptables 的继任者，IPv4/v6 统一管 |
| ADR-06 | 管理面板后端用 Go，不用 Python/Node | Python(FastAPI), Node(NestJS) | 单二进制部署、内存占用低、ARM64 交叉编译方便 |
| ADR-07 | 前端用 Vue3 + Element-Plus | React, Naive UI | 学习曲线缓、组件齐全、中文友好 |
| ADR-08 | 持久化用 SQLite，不用 PostgreSQL | PG, MySQL | 数据量极小、单文件备份、零运维 |
| ADR-09 | 不使用 Docker，全部宿主机原生 | Docker Compose | 树莓派资源有限；减少一层抽象；面板直接管控系统组件更直接 |
| ADR-10 | IPv4 兜底用 Cloudflare Tunnel | 自购 VPS + frp, 6to4 网关 | 默认免费方案；要 VPN 走 IPv4 时再加 VPS |

## 8. 风险与对应

| 风险 | 等级 | 对应措施 |
|---|---|---|
| 防火墙误操作锁死 SSH | 高 | 30 秒自动回滚机制；面板始终通过 VPN/内网访问 |
| 运营商封 51820 等常见 UDP 端口 | 中 | 端口可配置；Cloudflare Tunnel 无法转 UDP，最坏需自购 VPS |
| 阿里云 AK 泄露 | 高 | 强制子账号 + 最小权限 + 落盘 600 + 面板 mask 显示 |
| 树莓派 SD 卡损坏 | 中 | data 目录建议挂外置 SSD/U盘；提供一键备份脚本 |
| Let's Encrypt 限流 | 低 | acme.sh 自带重试退避；测试环境用 `--staging` |
| 家庭 IPv6 前缀被运营商频繁更换 | 中 | DDNS 5 分钟轮询，最坏 5 分钟内恢复 |
| 公网暴露管理面板 | 高 | 默认监听不绑 0.0.0.0；nftables 默认规则不放行 8443 |
| apt upgrade 覆盖 nginx/nftables 配置 | 低 | 面板生成的文件放在独立目录（sites-enabled / nftables.d），不动主配置 |
| 组件版本冲突（宿主机原生的代价） | 低 | Debian 12 stable 源版本锁定；ddns-go / pi-gateway 是独立二进制不受影响 |
