## 1. 项目背景

### 1.1 问题陈述

用户在家里有一台树莓派作为私人服务器，希望实现：

1. **大部分服务不对外暴露**，仅通过 VPN 接入家庭局域网时可访问（如 NAS、Home Assistant、SSH、私有 Git 等）。
2. **少数服务直接暴露到公网**（如博客、相册分享），通过域名 + HTTPS 访问。
3. 由于家庭宽带**只有公网 IPv6**（IPv4 是运营商级 NAT），需要解决：
   - 公网入口的 IP 漂移（依靠 DDNS）
   - 证书自动签发（HTTP-01 不可用，需走 DNS-01）
   - IPv4 客户端访问兜底（Cloudflare Tunnel / VPS 中转）
4. **防火墙可视化**：树莓派直接暴露在公网 IPv6 上，需要精确控制入站流量。
5. 上述能力需要**一个简单的 Web 管理界面**统一管理，类似 `lucky666.cn`，但**自主可控、代码自有**。

### 1.2 现有方案问题

用户曾考虑 OpenWrt + OpenVPN，但二者职责被混淆：

- OpenWrt 是路由器固件，与 VPN 协议无强绑定。
- OpenVPN 只是 VPN 协议的一种实现，与"公网入口/反代/SSL"是两层关注点。

**本项目明确分层**：公网入口层（A）、远程接入层（B）、防火墙层（C）独立设计、独立部署，互不耦合。

## 2. 项目目标

### 2.1 业务目标

| 编号 | 目标 | 度量 |
|---|---|---|
| G1 | 远程接入家庭内网 | 任意有 IPv6 的网络下，5 秒内通过 VPN 连上家里 |
| G2 | 公开服务可访问 | 域名访问 + 自动 HTTPS，证书到期前自动续期 |
| G3 | 统一可视化管理 | 全部能力在一个 Web 面板内完成配置，无需 SSH |
| G4 | 自主可控 | 全套开源、数据本地、不依赖任何商业 SaaS 协调服务 |
| G5 | 低运维 | 安装一次后 6 个月内无需手动介入（证书、IP 变更全自动） |
| G6 | 安全可控 | 可视化防火墙，精确控制 IPv4/IPv6 入站流量 |

### 2.2 非目标（不在本项目范围）

- 不做企业级多租户
- 不做 ACL / 流量审计 / 内容过滤（家用场景过度设计）
- 不做高可用集群（单树莓派即可）
- 不做自定义内核路由策略（保持 Linux 默认）
- 不替代 OpenWrt 路由器系统（本项目跑在树莓派应用层）
- 不使用 Docker / 容器化（宿主机原生 + systemd）

## 3. 用户角色

| 角色 | 说明 | 能力 |
|---|---|---|
| 管理员（Owner） | 家里的技术决策者，即用户本人 | 全部功能 |
| 来宾客户端 | VPN 接入者（家人、自己手机） | 仅有自己的 WireGuard 配置 |

### 4.2 用例清单

#### UC-01 DDNS 自动更新
- **目的**：家里公网 IPv6 变动时，自动把新地址同步到阿里云 DNS 的 AAAA 记录。
- **触发**：定时（默认 5 分钟）轮询本机 IPv6 地址；地址变化即触发。
- **输入**：阿里云 AccessKey、域名列表、记录名（如 `home.example.com`）。
- **输出**：阿里云 DNS 更新成功；管理面板看到"上次更新时间 / 当前 IPv6"。
- **失败处理**：连续 3 次失败 → 面板告警 + 写入日志。

#### UC-02 SSL 证书自动签发与续期
- **目的**：为暴露的域名签发 Let's Encrypt 证书；60 天前自动续期。
- **方式**：`acme.sh`（宿主机安装）+ 阿里云 DNS-01 验证，签发**泛域名 `*.example.com`**。
- **输入**：域名、阿里云 AccessKey（与 DDNS 可共用）。
- **输出**：`fullchain.pem` + `privkey.pem`，自动挂载到 nginx 并 reload。
- **失败处理**：续期失败提前 20 天告警；面板显示每张证书剩余天数。

#### UC-03 反向代理配置（公网入口）
- **目的**：把外部请求 `blog.example.com` 转发到内网 `192.168.1.50:8080`。
- **底层**：管理面板直接生成 nginx vhost 配置文件（`/etc/nginx/sites-enabled/xxx.conf`），调用 `nginx -s reload` 生效。
- **管理面板能力**：
  - 列出所有代理主机
  - 新增代理：填子域名 → 选证书 → 填后端 IP:Port → 一键启用
  - 启用 / 禁用 / 删除
  - 可选项：WebSocket 支持、HTTP/2、HSTS

#### UC-04 WireGuard 客户端管理
- **目的**：增删 VPN 客户端，生成配置文件 + 二维码（手机扫码导入）。
- **管理面板能力**：
  - peer 列表（名称、IP、最后握手时间、上下行流量、是否在线）
  - 新增 peer：输入名称 → 自动分配 IP（如 10.66.66.x）→ 生成密钥对 → 输出 `.conf` 文件 + 二维码
  - 启用 / 禁用 / 删除 peer（删除后立即生效，无需重启 WG）
- **网段**：默认 `10.66.66.0/24`（v4）+ `fd42:42:42::/64`（v6，可选）。
- **端口**：UDP 51820（可配置）。

#### UC-05 系统监控
- **采集项**：
  - CPU 使用率、负载
  - 内存使用率
  - **树莓派核心温度**（`/sys/class/thermal/thermal_zone0/temp`）
  - 磁盘使用率
  - 网络流量（每个网卡的收发字节）
- **展示**：仪表盘式首页，最近 1 小时趋势图。
- **告警**：温度 > 75°C 或 磁盘 > 90% 时面板顶部红色横幅。

#### UC-06 登录鉴权
- **认证**：账号 + 密码（bcrypt 存哈希），JWT 通过 HttpOnly Cookie。
- **首次启动**：安装脚本交互式设置初始密码。
- **修改密码**：面板内可改，需旧密码确认。
- **会话有效期**：默认 7 天，可配置。
- **失败保护**：连续 5 次失败 → 该 IP 锁定 15 分钟。

#### UC-07 服务一览（快捷入口）
- 用户可手动登记内网服务（名称、URL、图标），形成"家庭服务导航页"。
- 类似 Homepage / Dashy 的轻量版，但内嵌在管理面板中。

#### UC-08 防火墙可视化配置
- **目的**：通过 Web 界面管理树莓派的 nftables 防火墙规则，无需手写 nft 命令。
- **底层**：管理面板生成 nftables 规则集文件（`/etc/nftables.d/pi-gateway.nft`），调用 `nft -f` 加载。
- **管理面板能力**：
  - **区域概览**：公网入站（inet input）、VPN 入站（wg0 input）、转发（forward）三个区域的规则可视化
  - **服务模板**：预置常见服务模板（SSH/HTTP/HTTPS/WireGuard/DNS），一键放行
  - **自定义规则**：协议（TCP/UDP/ICMP）、端口（单个/范围）、来源 IP/网段（IPv4 + IPv6）
  - **启用/禁用**：单条规则可临时禁用而不删除
  - **规则排序**：拖拽排序，越靠前优先级越高
  - **实时预览**：修改后先预览最终 nft 规则集，确认后再应用
  - **安全锁**：30 秒内没有确认的规则变更自动回滚，防止把自己锁在外面
  - **当前连接**：展示 `conntrack` 活跃连接列表
- **默认策略**：
  - input：`drop`（默认拒绝所有入站）
  - 放行：lo / icmpv6(NDP 必须) / established,related / SSH / WireGuard(51820) / HTTP(80) / HTTPS(443)
  - forward：允许 wg0 → eth0（VPN 客户端访问内网）

## 5. 非功能性需求

### 5.1 性能
- 管理面板冷启动 ≤ 3 秒
- 单次 API 响应 P95 ≤ 200 ms（本地访问）
- 系统状态 WebSocket 推送间隔 2 秒
- 内存占用：管理面板后端 ≤ 80 MB；nginx ≤ 50 MB；其他组件合计 ≤ 50 MB

### 5.2 可用性
- 各服务异常自动重启（systemd `Restart=on-failure`）
- DDNS / 续期失败不影响其他模块
- 重启树莓派后 30 秒内全部服务恢复

### 5.3 安全
- 管理面板默认仅监听 `127.0.0.1` 或局域网段，**不暴露公网**（必须通过 VPN 或局域网访问）
- 所有密钥（阿里云 AK、WG 私钥、JWT secret）落盘前权限 600
- 阿里云 AK 强制使用**子账号**且仅授予 `AliyunDNSFullAccess`
- WG peer 删除立即生效
- 登录密码 bcrypt cost ≥ 12
- 防火墙规则变更 30 秒自动回滚机制，防止误操作锁死

### 5.4 可维护性
- 全部组件通过 systemd 管理（`systemctl status/start/stop/restart`）
- 配置数据集中在 `/opt/pi-gateway/data/` 目录，便于备份
- 日志统一输出到 journald，也可选配文件日志 `/opt/pi-gateway/data/logs/`
- 单二进制 + 静态前端，升级 = 替换二进制 + `systemctl restart pi-gateway`

### 5.5 可移植性
- ARM64 为主目标，AMD64 同样可跑（开发机调试）
- OS 要求：systemd + Debian 12（或兼容发行版），不依赖 Docker

## 6. 约束与假设

### 6.1 已确认约束
- 公网：**仅 IPv6**
- 域名：**阿里云**
- 部署方式：**宿主机原生 + systemd**（不使用 Docker）
- A 层方案：**裸 nginx + acme.sh + ddns-go**（全部 apt/二进制安装）
- VPN：**WireGuard**（替代用户原先想的 OpenVPN）
- 防火墙：**nftables**（Debian 12 默认，替代 iptables）
- IPv4 兜底：**Cloudflare Tunnel**（默认值，Web 服务用，免费）
- 管理面板：**自研** Go 后端 + Vue3 前端

### 6.2 假设
- 用户已有或愿意购买一个阿里云域名
- 用户能创建阿里云子账号并授权 `AliyunDNSFullAccess`
- 家里光猫/路由的 IPv6 已经分配到树莓派且可入站（防火墙允许）
- 用户家里手机/电脑等"内部"客户端，至少一部分网络环境有 IPv6（用于 VPN 拨入测试）

### 6.3 待用户提供
- [ ] 阿里云域名（如 `example.com`）
- [ ] 阿里云子账号 AccessKey ID / Secret
- [ ] Cloudflare 账号（用于 Tunnel）—— 可后置
- [ ] 树莓派 SSH 信息（部署阶段需要）
- [ ] 管理员初始密码

## 7. 验收标准

v1.0 验收以下场景全部通过：

1. **公网入口**：在外面用手机 IPv6 网络访问 `https://blog.example.com`，能看到树莓派上跑的博客，证书有效。
2. **VPN 接入**：在外面用手机扫码导入 WireGuard 配置，连上后可以访问家里 `http://192.168.1.x:xxxx` 内网服务。
3. **DDNS**：手动改家里 IPv6（或等待自然变化），5 分钟内阿里云 DNS 后台看到 AAAA 已更新。
4. **证书续期**：把证书有效期改成 < 30 天（测试技巧），观察 24 小时内自动续期成功。
5. **防火墙**：
   - 面板增加一条"放行 TCP 8080"规则 → 外部可访问 → 删除规则 → 外部不可访问
   - 删除 SSH 放行规则 → 30 秒内未确认 → 自动回滚 → SSH 恢复可用
6. **管理面板**：
   - 登录后能看到首页（CPU/内存/温度/磁盘）
   - 增删一个反向代理后，公网访问立即生效
   - 增删一个 WG peer 后，客户端连接行为符合预期
7. **重启恢复**：树莓派断电重启后，所有服务自动起来，无需任何手动操作。
