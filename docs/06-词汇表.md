## A. 网络与协议

### DDNS（Dynamic DNS）
动态域名解析。家庭宽带的公网 IP（v4 或 v6）经常变，DDNS 工具定时把"当前 IP"同步到 DNS 服务商，使域名始终解析到家里。

### A 记录 / AAAA 记录
DNS 中的 IP 类型记录：
- **A 记录**：域名 → IPv4
- **AAAA 记录**：域名 → IPv6
- 本项目主用 **AAAA**

### CNAME
别名记录，域名 → 另一个域名。Cloudflare Tunnel 用 CNAME 指向 `<uuid>.cfargotunnel.com`。

### IPv6-only
家里只有公网 IPv6，没有公网 IPv4。运营商 IPv4 走 CGNAT（运营商级 NAT），无法做端口映射。

### CGNAT / NAT4
运营商级 NAT。多家用户共用一个公网 IPv4，普通用户无法做端口映射。常见于电信/移动光纤。

### IPv6 防火墙
路由器/光猫对入站 IPv6 流量的默认拒绝策略。需要明确放行树莓派的入站端口（443、51820 等）。

### Full Cone NAT
最宽松的 NAT 类型；只有这种 NAT 下"打洞"才容易成功。家用宽带罕见，主要 IPv6 不需要 NAT。

## B. VPN 相关

### WireGuard
现代 VPN 协议，基于 UDP，配置简单、性能极高、Linux 内核态原生支持。本项目 VPN 选型。

### Peer
WireGuard 术语，指 VPN 的一个端点。服务端和每个客户端都是 peer。

### AllowedIPs
WireGuard peer 配置项，定义"哪些目标 IP 走这个 peer"。
- 客户端的 `AllowedIPs = 10.66.66.1/32, 192.168.1.0/24` 表示只把家里的网段走 VPN
- 客户端的 `AllowedIPs = 0.0.0.0/0, ::/0` 表示全部流量走 VPN

### Endpoint
WireGuard 客户端配置中的服务端地址（域名 + UDP 端口）。本项目通常是 `vpn.example.com:51820`。

### Handshake
WireGuard peer 之间最近一次握手时间。如果 > 3 分钟没握手，通常意味着断连。

### OpenVPN
传统 VPN 协议，用户态实现，配置复杂、性能低。**本项目不使用**。

### Tailscale / Headscale
基于 WireGuard 的服务：自动打洞 + NAT 穿透 + 中心化协调。Headscale 是 Tailscale 协调服务的开源自建版。**本项目暂不使用，保持简单**。

## C. 证书与 ACME

### Let's Encrypt
免费的公益 CA，签发免费 90 天有效期的 SSL 证书。绝大多数网站的 HTTPS 来源。

### ACME 协议
Let's Encrypt 用来自动签发证书的协议。

### HTTP-01 验证
ACME 验证方式之一：CA 通过 80 端口访问 `http://你域名/.well-known/acme-challenge/xxx` 校验你拥有该域名。
- **本项目不能用**（IPv6-only，无 IPv4 公网，且很多场景 80 端口不可达）

### DNS-01 验证
ACME 验证方式之一：在 DNS 上添加一个 TXT 记录证明域名所有权。
- **本项目主用方式**
- 优点：可以申请泛域名（`*.example.com`），且不需要服务器在公网可达
- 缺点：必须能通过 API 改 DNS（所以才需要阿里云 AK）

### 泛域名证书
`*.example.com` 这种证书，能匹配该域名下所有一级子域名（`a.example.com`、`b.example.com` 等）。

### acme.sh
开源的 ACME 客户端，shell 实现，支持几十种 DNS 提供商。本项目通过 `curl` 安装到宿主机。

## D. 反向代理

### 反向代理（Reverse Proxy）
外部请求先到代理（如 nginx），代理转发到内部真正的服务。好处：统一 SSL 入口、隐藏后端、多服务复用 443。

### 子域名分发
不同子域名转发到不同后端服务：
- `blog.example.com` → 192.168.1.50:8080
- `git.example.com`  → 192.168.1.51:3000

### nginx
高性能 Web 服务器 / 反向代理。本项目通过 `apt install nginx` 安装，管理面板直接生成 vhost 配置文件控制反代行为。

### vhost 配置文件
nginx 的虚拟主机配置，每个被反代的子域名对应一个 `.conf` 文件，放在 `/etc/nginx/sites-enabled/` 目录。面板通过模板渲染生成这些文件。

### nginx -t
nginx 配置语法检查命令。面板每次修改 vhost 后都先 `nginx -t`，通过才 `nginx -s reload`。

### nginx -s reload
让 nginx 重新加载配置（不中断已有连接）。面板在反代或证书变更后自动执行。

## E. 防火墙

### nftables
Linux 内核防火墙框架，iptables 的继任者。Debian 12 默认使用。本项目防火墙选型。

### nft
nftables 的命令行工具。如 `nft list ruleset` 列出所有规则，`nft -f xxx.nft` 原子加载规则文件。

### 规则集（Ruleset）
nftables 中所有表（table）、链（chain）、规则（rule）的总称。

### 表（Table）
nftables 的顶层组织单元。本项目使用 `table inet pi_gateway`，`inet` 族表示 IPv4 + IPv6 统一管理。

### 链（Chain）
挂载在表下的规则容器。本项目主要三条链：
- `input`：控制入站流量（公网 → 树莓派）
- `forward`：控制转发流量（VPN 客户端 → 内网）
- `output`：出站流量（通常不限制）

### 规则（Rule）
具体的匹配 + 动作。如：`tcp dport 443 accept`（放行 HTTPS）。

### 默认策略（Policy）
链中没有任何规则匹配时的动作。本项目 input 链默认 `drop`（拒绝一切未明确放行的流量）。

### 原子加载
`nft -f` 命令将整个规则文件作为一个事务加载，要么全部成功要么全部失败，不会出现加载到一半的中间状态。

### 自动回滚
本项目的安全机制：应用新防火墙规则后启动 30 秒倒计时，用户必须在面板点"确认"。超时未确认则自动恢复旧规则，防止误操作把自己锁在外面。

### conntrack
Linux 连接跟踪子系统，记录所有活跃网络连接的状态。面板通过读 conntrack 表展示当前连接列表。

### NDP（Neighbor Discovery Protocol）
IPv6 的邻居发现协议，类似 IPv4 的 ARP。防火墙**必须放行 ICMPv6 NDP 报文**，否则 IPv6 网络完全不可用。

## F. Cloudflare 相关

### Cloudflare
全球 CDN/DNS/安全服务商。

### Cloudflare Tunnel
Cloudflare 提供的"反向隧道"。家里的 cloudflared 客户端主动连接 Cloudflare 边缘，外部访问通过 Cloudflare 转发到家里。
- **不需要任何入站端口**
- 免费
- 仅支持 HTTP/HTTPS（本项目 IPv4 兜底用）

### cloudflared
Cloudflare Tunnel 的客户端二进制。本项目作为 systemd 服务运行。

## G. 项目自有术语

### A 层 / 公网入口层
本项目的逻辑分层之一，负责：DDNS、SSL、反代。组件：ddns-go + acme.sh + nginx。

### B 层 / 远程接入层
本项目的逻辑分层之一，负责：VPN 拨入。组件：WireGuard。

### C 层 / 防火墙层
本项目的逻辑分层之一，负责：入站流量控制。组件：nftables。

### 管理面板 / Pi-Gateway
我们自研的 Web UI + 后端服务，统一管 A、B、C 三层。

### Owner
管理员，唯一登录角色。

### 服务导航
管理面板内的"内网服务快捷入口"页面，类似 Homepage。

## H. 部署相关

### systemd
Linux 系统和服务管理器。本项目所有组件（nginx、WireGuard、nftables、ddns-go、pi-gateway、cloudflared）全部通过 systemd 管理生命周期。

### systemd timer
systemd 的定时器单元，替代 cron。本项目 acme.sh 续期检查通过 `acme-renew.timer` 实现。

### ARM64 / aarch64
树莓派 4/5 的 CPU 架构。Go 编译时 `GOARCH=arm64`。

### `/etc/wireguard/wg0.conf`
WireGuard 服务端配置文件位置。

### `/etc/nftables.d/pi-gateway.nft`
面板生成的防火墙规则文件，被 `/etc/nftables.conf` include。

### `/etc/nginx/sites-enabled/*.conf`
面板生成的 nginx vhost 配置文件位置。

### `/sys/class/thermal/thermal_zone0/temp`
树莓派核心温度的内核接口，读出来除以 1000 就是摄氏度。
