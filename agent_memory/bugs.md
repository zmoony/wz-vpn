# 已知问题 / 风险

- 本地终端缺少可直接调用的 `go` 运行时，后端编译和 Go 测试可能无法在当前环境完成。
- 当前机器大概率不存在真实的 WireGuard 宿主环境，因此 WireGuard 系统级行为只能通过适配层设计和非破坏性命令约定来保证结构正确，无法完成真实联调。
- 前端已完成构建验证，但产物体积较大，Vite 给出 chunk size warning；后续可以考虑路由懒加载和手动分包。
- 当前 WireGuard 客户端配置依赖环境变量 `PI_GATEWAY_WG_PUBLIC_KEY` 提供服务端公钥；若未配置，生成的客户端配置只能作为占位示例，不能直接导入使用。
- 当前 DDNS 适配层写入的是 Pi-Gateway 管理的受管配置文件，并通过 `PI_GATEWAY_DDNSGO_RELOAD_COMMAND` 触发外部 reload；是否与现网 ddns-go 原生配置完全一致，仍需在目标环境核对。
- 反向代理适配层依赖本机存在可执行的 `nginx` 命令，以及目标目录权限正确；本轮未在真实 nginx 环境中验证 `-t` / `reload`。
- DDNS 编辑时前端不会回显历史 `AccessKey Secret`，更新现有配置时需要重新输入 Secret。
- 证书管理适配层目前默认通过 `cmd /c` 拼接环境变量和 `acme.sh` 命令，更适合真实 Linux 部署环境前再做一次命令形态核对；当前会话无法验证真实 `acme.sh` 执行。
- 证书状态依赖读取 `fullchain.pem` 的首张证书；如果安装目录为空或证书未写入，页面只会显示配置，不会显示到期时间。
- 证书编辑时前端同样不会回显历史 `AccessKey Secret`，更新现有配置时需要重新输入或保留后端已有值。
- 防火墙这轮只覆盖 `input` 链，尚未纳入 `forward` 链，因此 WireGuard 到内网的转发策略仍不在面板控制范围内。
- 防火墙适配层依赖本机存在可执行的 `nft` 命令、规则文件写权限、以及目标系统允许当前进程修改 nftables；当前会话无法验证真实 apply/rollback。
- 防火墙待确认状态虽然已落盘，但自动回滚定时器仍依赖当前服务进程驻留；如果在待确认窗口内进程异常退出，需要靠下次启动时的 pending 恢复逻辑兜底。
- 当前 forward 链只支持一个可配置内网 CIDR 和固定 `wg0 -> 内网` 放行场景，尚不支持多网段、通用转发规则或 NAT。
- 当前 `forward` 独立规则模型仍是最小版，只支持来源/目标 CIDR、`any/tcp/udp` 和单个目标端口，尚未支持接口匹配、源端口、动作类型或 NAT。
- 当前前端仍保留旧的单网段 `forward` 兼容配置；当独立 `forward` 规则列表为空时才会参与渲染，这个优先级行为尚未在真实宿主环境联调。
- 当前 `conntrack` 页面依赖宿主机安装 `conntrack-tools` 并允许执行 `conntrack -L`；当前会话无法验证真实输出格式是否覆盖所有协议和状态变体。
- 当前 `conntrack` 解析器只提取来源/目标地址与端口、协议和最后一个状态词；面对非常规输出、NAT 复合行或不同发行版格式时，可能需要再补兼容分支。
- 当前安装脚本和 systemd unit 是按 Linux 宿主机假设编写的；当前开发环境是 Windows，无法在本机真实执行 `install.sh`、`systemctl daemon-reload` 或 service 启停联调。
- 当前安装脚本默认要求仓库根目录存在已构建好的 `pi-gateway` 二进制；脚本本身不负责 Go 构建或交叉编译。
- 当前设置页只覆盖最关键的 WireGuard 运行参数；其它模块的路径型或进程级配置仍主要依赖启动时 env，而不是统一从设置页生效。
- WireGuard 设置修改后会影响后续 Peer 创建、运行态接口操作和部分防火墙渲染，但不会自动批量回写已有 peer 记录中的历史 Endpoint/DNS 字段。
- 2026-05-13：当前终端 PowerShell 会话仍拿不到新的 `go` PATH，需继续使用 `C:\Program Files\Go\bin\go.exe` 绝对路径执行 Go 验证；这不是代码问题，但会影响后续命令复现。
- 2026-05-13：反向代理证书选择已切到根域名模式，但旧数据只是在列表读取时按证书路径做“尽力反推”；如果历史反代记录的证书路径与证书管理中的安装路径不一致，前端下拉里可能仍显示为空，需要用户重新选择一次证书根域名并保存。
- 2026-05-19：防火墙基础规则会在“当前没有任何 input 规则”时自动初始化，但只写入数据库、不自动 apply；首次进入后仍需要用户手动点击“应用”才能真正下发到 nftables。
